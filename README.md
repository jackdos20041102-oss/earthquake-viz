## 一、可视化方案旨在解答的问题

全球每年发生数千次有感地震，但公众对地震活动的认知通常局限于新闻报道中的个别事件，缺乏对其空间分布、时间规律和深层结构的整体理解。本项目将 USGS（美国地质调查局）公开的地震观测数据转化为一个多视图交互探索系统，试图回答以下核心问题。

**空间分布的结构规律**：全球地震活动是均匀分布的，还是呈现出明显的带状集中？太平洋火环带（Ring of Fire）在实际数据中的轮廓有多清晰？哪些区域是全球地震活动最密集的热点？亚洲、美洲、大洋洲三大板块交汇区的地震频次和强度是否存在显著差异？

**震级与深度的物理关联**：浅源地震（<70km）、中源地震（70-300km）和深源地震（>300km）在震级分布上是否存在显著差异？深源高震级地震是否更集中于特定的俯冲带区域？震级和深度之间是否存在某种分层结构——例如深源地震是否倾向于出现在特定的震级区间？

**时间维度的周期与趋势**：近期的地震活动是否存在明显的时间集中？历史数据（2021-2026年）中M5.0+地震的年际变化趋势如何？是否存在某些月份或季节地震活动更为频繁的规律？

**区域对比分析**：各大洲的地震活动在数量占比和震级分布上有何差异？大洋洲（包含环太平洋区域的大量岛弧）在统计上是否被低估？

这四个问题通过多视图联动机制有机关联——用户在地图上选择区域时，时间分布、震级统计和深度散点会同步过滤；在时间轴上刷选时段时，地图和所有统计图表也会实时联动更新。

## 二、设计决策的依据

### 数据编码策略

**世界地图散点图** 是整个系统的核心视图，使用 D3.js 的 Natural Earth 投影将全球地震事件映射到二维平面。每个地震事件以圆点表示，圆点的半径编码震级大小（M3级2.5px至M7+级10px，采用分段映射而非线性映射以增强视觉区分度），颜色编码震级等级（绿色→黄色→橙色→红色的色阶对应M3→M7+），M6+级地震额外添加发光滤镜和脉冲动画以突出显示。地图支持鼠标滚轮缩放和拖拽平移，便于用户从全球概览深入到区域细节。

**时间分布散点图** 将每次地震事件按时间轴水平排列，纵轴映射震级，形成一个时间-震级的二维分布图。选择散点而非折线或面积图，是因为地震事件是离散的，折线图会暗示事件之间存在连续性。该视图支持 D3 brush 交互——用户可以拖拽框选任意时间区间，所有其他视图会实时响应，仅展示所选时段内的地震数据。

**深度×震级散点图** 以震级为横轴、深度为纵轴（向下为正，符合地质学惯例），直观揭示两个关键物理量之间的分布关系。背景使用三段半透明色带区分浅源（<70km，绿色）、中源（70-300km，蓝色）和深源（>300km，紫色）区域，散点颜色同步映射深度分类，使用户无需参照图例即可识别深度层级。

**震级分布柱状图** 使用 D3.js 绘制的柱状图，将地震按 M2-3、M3-4、M4-5、M5-6、M6-7、M7+ 六个区间分组统计，每个柱条颜色对应该震级的标准色。柱顶标注具体数值，用户可以直接读取各区间的精确计数。选择柱状图而非直方图，是因为震级区间是人为定义的离散分组而非连续变量的等距切分。

**区域统计环形图** 使用 ECharts 绘制，按大洲统计地震数量占比。选用甜甜圈形（中空环形）而非实心饼图，使各段弧长更易于视觉比较，中央空白减少视觉杂乱。颜色方案为每个大洲分配独立的语义颜色（亚洲红、美洲橙、大洋洲绿、欧洲蓝、非洲黄、南极紫），确保在多视图间切换时用户能快速识别区域归属。

### 替代方案的取舍

曾考虑使用 3D 地球呈现地震分布（Three.js globe），能够更直观地展示环太平洋火环带的三维结构。但实际测试发现：3D 地球的旋转交互在数据点密集时（2000+点）存在性能问题，且地球背面的数据点无法观察，反而降低了信息的可达性。最终选用 2D 投影 + 缩放平移的方案，在全局可见性和交互流畅性之间取得更好的平衡。

曾考虑使用热力图代替散点图展示地震密度，但热力图会模糊单个事件的精确位置和震级差异，且无法支持逐点 hover 和 click 交互。当前的散点方案通过半径和颜色双重编码，在保持个体信息可达性的同时也能呈现整体分布趋势。

曾考虑在时间轴中使用面积堆叠图按震级分层展示频次变化，最终选择离散散点的原因是地震是离散事件，面积图会引入不存在的连续性暗示。

## 三、外部资源引用

### 数据来源

- **USGS Earthquake Hazards Program**：https://earthquake.usgs.gov/
  - 近30天 M2.5+ 地震数据：通过 USGS GeoJSON Feed API 获取，约 2000 条记录。
  - 历史数据（2021-2026年 M5.0+ 地震）：通过 USGS FDSN Event Web Service API 逐年查询，共约 9500 条记录。
  - 数据字段：时间戳、经纬度、深度、震级、地名、海啸标识、显著性指数等。

## 四、开发流程概述

### 团队构成

本项目为独立完成的个人作业，无团队分工。

### 开发阶段

**数据获取阶段**

评估了多个候选数据集（中国城市空气质量、中国人口迁徙、电影票房数据），最终选择 USGS 地震数据的原因是：API 完善且无需认证（零门槛获取）、数据字段天然适合空间+时间+多维度分析、地理分布具有高度可视化价值（火环带结构）、公众对地震话题具有普遍认知基础。编写 Python 下载脚本 `download_earthquake_data.py`，实现分时段批量查询和 JSON 持久化。

**架构搭建阶段**

使用 Vite 初始化 Vue 3 项目，确定组件化架构：`App.vue` 管理全局状态和组件间联动，`dataLoader.js` 统一数据加载与解析逻辑。核心设计决策是将筛选状态（震级范围、时间范围）集中在 App 层通过 `computed` 广播至所有子组件，避免组件间的直接通信和状态不一致问题。

**图表开发阶段**

按依赖关系依次开发：数据加载→世界地图→详情面板→统计卡片→震级分布→时间分布→深度散点→区域饼图→地震列表。世界地图是最复杂的组件，涉及 D3 地理投影、TopoJSON 解析、zoom 行为绑定、SVG 发光滤镜和脉冲动画、2000+数据点的性能优化。时间轴的 brush 交互与全局状态联动也需要仔细处理事件冒泡和状态同步。

**交互联动阶段**

实现地图点击→详情面板更新、时间轴 brush→全局过滤、震级按钮→地图过滤、列表排序切换、数据模式切换（近30天/历史数据）等交互逻辑。关键挑战在于确保所有视图对同一筛选条件的响应一致。

**样式调优阶段**

初版使用深色主题（黑色背景），后根据反馈调整为浅色自然色调方案。主要挑战包括：`ResizeObserver` 在 flex 布局容器中触发无限循环（通过缓存上次宽度+阈值判断+固定高度解决）、D3 SVG 在不同容器尺寸下的自适应（改用固定像素尺寸替代 viewBox 百分比）、图表轴标签和图例的空间规划（增大 margin 并调整标签位置）。

## 五、可视化功能说明

应用由以下功能区块组成：

**顶部导航栏**：项目标题、数据模式切换按钮（近30天 / 历史数据），sticky 定位保持可见。

**统计概览栏**：5 个关键指标卡片——地震总数、最大震级、平均震级、平均深度、海啸预警次数，每个卡片配有语义化图标和对应强调色，实时响应筛选条件变化。

**核心地图区**（左）+ **地震详情面板**（右）：
- 世界地图：D3 Natural Earth 投影，支持缩放/平移/震级筛选（全部/M3+/M5+/M6+/M7+），图例标注震级-尺寸-颜色映射。
- 详情面板：点击或悬停地震点后显示完整信息（震级等级、位置、时间、深度类型、坐标、海啸状态），提供 USGS 详情页外链。

**下方 2×2 图表网格**：
- 时间分布散点图：支持 brush 框选时间范围，联动过滤所有视图。
- 深度×震级散点图：三段深度色带背景，揭示深度-震级关系。
- 区域统计环形图：ECharts 甜甜圈图，按大洲统计占比。
- 震级分布柱状图：六段震级区间计数。

**地震列表**：支持按时间/震级/深度三种排序，每条记录显示震级徽章、位置、时间、深度指示条和海啸标识，支持点击选中联动地图和详情面板。

全局交互：时间轴 brush 筛选→所有视图联动、地图震级过滤→散点/列表联动、数据模式切换→全量数据重载。

## 六、本地运行

```bash
# 1. 下载地震数据（需要 Python 3.6+）
python download_earthquake_data.py

# 2. 安装前端依赖
cd earthquake-viz
npm install

# 3. 启动开发服务器
npm run dev
```

访问 `http://localhost:3000`

### 构建部署

```bash
npm run build
```

构建产物位于 `dist/` 目录，可直接部署至 GitHub Pages 或任意静态服务器。
